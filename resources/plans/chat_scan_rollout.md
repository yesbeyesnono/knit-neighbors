# 채팅 자동 점검 — 시작 절차와 문구 (2026-11-11 대표 확정)

기능은 만들어져 있고 **꺼져 있다**(콘솔 › 오늘 › 채팅 점검의 [켜기], 서버 `jigi_config.chat_scan`).
회원에게 한 약속(지금 방침: "1:1·단체 채팅은 AI가 읽지 않으며, 신고가 접수된 경우에 한해 신고된 메시지만 확인")을 먼저 바꾸고 알린 뒤, **안내한 날로부터 7일 뒤**에 켠다.
방침 문구는 시행 전에 법률 검토를 한 번 받는 것을 권한다.

## 대표가 "채팅 점검 안내 시작해줘"라고 하면 Claude 가 할 일

1. 시행일 = 안내하는 날 + 7일(아래 ○월 ○일 자리에 넣음).
2. `docs/privacy.html` 의 **운영 목적의 AI 검토** 문단에서 아래 '지금' 문장을 '바꾼 뒤' 문장으로 교체하고, 맨 위 개정 줄에 `○월 ○일: 채팅 자동 안전 점검 추가(시행 ○월 ○일)`을 덧붙인다.
3. 푸시(`[skip ci]` 면 Pages 수동 빌드) → `gh workflow run sync-legal.yml -R yesbeyesnono/knitup-home` → `curl https://app.knitup.co.kr/privacy.html` 로 확인.
4. 회원 안내: 콘솔 › 알리기 › 공지·알림 보내기 › '첫 화면 고정 공지 카드'에 아래 안내문을 '시트로 먼저' 켜서 저장(= 앱 안 '공지·새 소식'에도 자동으로 남음). 문구는 올리기 전에 대표에게 한 번 더 보여 준다.
5. 스토어 개인정보 표시 확인: App Store '사용자 콘텐츠 › 기타 사용자 콘텐츠(메시지)'·Play 데이터 보안 '메시지'의 목적에 '사기 방지·보안'이 들어 있는지 보고, 없으면 대표에게 알린다.
6. 시행일 아침에 텔레그램 예약 알림(`jigi_reminders`): "오늘부터 채팅 점검을 켜는 날 — 콘솔 › 오늘 › 채팅 점검 › [켜기]".
7. 켠 뒤 2주는 걸린 건을 보며 규칙을 다듬는다(규칙은 DB 함수 `_chat_rules`).

## 개인정보처리방침 문구

**지금**

> **1:1·단체 채팅은 AI가 읽지 않으며**, 신고가 접수된 경우에 한해 신고된 메시지만 확인합니다.

**바꾼 뒤**

> 안전한 이용을 위해 채팅 메시지는 **자동으로 점검**됩니다(금전 요구·사기, 앱 밖 연락 유도, 성적 표현·괴롭힘, 위협, 미성년자 보호 관련 표현 감지). 평소에는 운영진이 채팅을 열람하지 않으며, **위험이 감지되었거나 신고가 접수된 경우에 한해** 해당 메시지와 그 앞뒤 일부를 운영진이 확인합니다. 감지된 메시지는 판단을 돕기 위해 연락처·숫자를 가린 뒤 AI(외부 처리 위탁)로 한 번 더 검토될 수 있습니다. 분쟁·수사기관의 적법한 요청이 있는 경우 해당 대화를 필요한 기간 보존하고 제출할 수 있습니다.

## 회원 안내문 (첫 화면 공지 · 공지·새 소식)

제목: **채팅을 더 안전하게 만들어요**

> ○월 ○일부터 채팅에 자동 안전 점검이 들어가요. 돈을 먼저 보내 달라는 요청, 앱 밖으로 끌어내는 연락, 불쾌한 표현 같은 위험 신호를 기계가 찾아내요.
>
> 평소에는 아무도 대화를 읽지 않아요. 위험 신호가 있거나 신고가 들어온 경우에만 운영진이 그 부분을 확인해요.
>
> 자세한 내용은 개인정보처리방침에서 볼 수 있어요.
